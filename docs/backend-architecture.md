# Устройство бэкенда

## Границы ответственности

- `domain`: модели, типы и интерфейсы репозиториев. Без HTTP и моделей речи.
- `application`: сценарии заказа, агент, проверка действий и аудиопротокол.
- `infrastructure`: SQLAlchemy, Redis, HTTP-клиенты, Qwen и модели речи.
- `presentation`: HTTP/WebSocket, валидация запросов и обработка ошибок.
- `entrypoint`: конфигурация, Dishka, жизненный цикл и запуск процессов.

Реализации подключаются в IoC, а не создаются внутри бизнес-сервисов.
Репозитории выполняют `flush`, но не владеют транзакциями.

## Разговор и оформление

`OrderAgent` координирует отдельные компоненты:

1. `ContextBuilder` собирает меню, корзину и историю реплик.
2. `PlanningService` запрашивает у модели план действий.
3. `ActionExecutor` передаёт действия проверкам корзины и получения заказа.
4. `CheckoutService` оформляет заказ при наличии необходимых данных.
5. `ReplyGenerator` запрашивает ответ Qwen и проверяет его согласованность
   с реально выполненными действиями.

Модель не изменяет базу напрямую. Проверяются SKU, количество, наличие,
упоминание позиции клиентом и параметры получения. Неоднозначное название
не превращается автоматически в произвольную позицию меню.
Отклонённое действие не считается выполненным.

Ответы пишет Qwen. Промпты отделены от оркестрации; аварийные сообщения и
инструкции повторного запроса находятся в отдельных файлах.
Цена берётся из оформленного заказа и форматируется в рублях и копейках.

`OrderUseCases.create_confirmed` создаёт позиции, рассчитывает сумму и
подтверждает заказ в одной транзакции. Для самовывоза адрес не требуется.
Повторное пользовательское подтверждение не нужно.

`InMemorySessionStore` живёт в APP scope. Блокировка отдельной сессии
сериализует одновременные реплики. Это локальное хранилище: незавершённые
разговоры не переживают перезапуск и не распределяются между workers.
Для нескольких экземпляров приложения нужен внешний SessionStore.

## Голос

Браузер передаёт PCM через `/api/v1/pub/agent/audio`.
`AudioBridge` пересылает пакеты голосовому процессу, не занимаясь ASR.

- `UtteranceBuffer`: кадры PCM, предзапись, выделение реплики и лимиты.
- `SileroDetector`: VAD, отдельное состояние для каждого звонка.
- `SpeechModels`: Parakeet для STT, Silero v5_ru для TTS.
- `HttpOrderingAgent`: типизированное обращение к API заказа.
- `VoiceCall`: последовательность прослушивания, ответа и воспроизведения.

Это half-duplex: во время ответа микрофон не обрабатывается, чтобы голос
агента не попадал обратно в заказ. Перебивание агента пока не реализовано.
Отключение клиента не вызывает повторное аварийное закрытие сокета.

Модели загружаются один раз на экземпляр голосового приложения.
Голосовой процесс запускается на хосте:

```sh
poetry run python -m src.entrypoint.voice
```

`scripts/voice_server.py` сохранён как совместимый запускатель.
Бэкенд и фронтенд запускаются через `docker-compose.local.yml`.

## Тексты и диагностика

- `application/agent/config/prompts.py`: системные промпты.
- `application/agent/config/messages.py`: инструкции и аварийные ответы.
- `application/agent/config/language.py`: языковые маркеры проверок.
- `application/messages.py`: ошибки бизнес-сценариев и схем.
- `application/logging/messages.py`: шаблоны логов.
- `application/voice/constants.py`: параметры и сообщения аудиопротокола.
- `infrastructure/implementation/*/constants.py`: настройки адаптеров.
- `presentation/constants.py`: маршруты и сообщения транспорта.

Ключи JSON, имена полей ORM и Enum остаются рядом с контрактами: перенос
каждого структурного литерала в глобальную константу ухудшает читаемость.
`AgentLog`, `SocketLog`, `VoiceLog` скрывают форматирование диагностики.
Логи содержат реплики, поэтому в production требуют защиты и политики
хранения персональных данных.

## Проверки

```sh
poetry run pytest tests -q
poetry run black --check src tests scripts/voice_server.py
poetry run isort --check-only src tests scripts/voice_server.py
poetry run pylint src
```

Тесты покрывают диалог, валидацию действий, конкурентные сессии,
транзакцию оформления, схемы каталога и аудиопротокол. Они не заменяют
интеграционный прогон с PostgreSQL, Docker, GPU и микрофоном.
